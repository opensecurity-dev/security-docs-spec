# Release Notes - v0.1.0

**Release date:** 2026-11-08

## Overview

First release of `security-docs-spec`: an open format for the self-attested security documents a cloud service
publishes, and `secdocs`, a Go CLI that lints and renders it.

One JSON file per product holds the facts and the documents. People and tools fill it in, `secdocs lint` says what
is still to be done, and `secdocs render` and `secdocs export` publish the result as Markdown and JSON.

## Highlights

- **A fact is stated once.** Hosting, encryption, backups, data lifecycle and the incident-notification window are
  typed values that any document can include, so two pages cannot disagree.
- **Every claim says how true it is.** A status (implemented, partial, planned, alternative, not-applicable or todo)
  and a verification level (unverified, reviewed or verified). Partial and planned claims must state their gap.
- **Lint is the to-do list.** Findings carry a rule ID, a severity and a JSON path.
- **Rendering cannot leak.** Each claim is `public`, `nda` or `internal`, and content above the chosen audience is
  removed before anything is written.
- **Free to reuse.** The format builds only on NIST SP 800-53, FedRAMP's 2026 rules and RFC 9116. Restricted
  frameworks are named by identifier only.

## Added

### The document set

| Document | Slug | Contents |
|---|---|---|
| Security overview | `security-overview` | Sections of practices, plus fact groups |
| Security response | `security-response` | Reporting channels, process, scope, safe harbor, acknowledgements |
| Subprocessors | `subprocessors` | Name, purpose, locations, headquarters, data categories |
| Data handling | `data-handling` | Deletion, retention, backups, location, transfers |
| Incident response | `incident-response` | Notification commitment, process, drills, history |
| Availability | `availability` | An uptime commitment, or a statement that none is made |
| Custom | any | Sections, for anything else |

Fact groups: `hosting`, `encryption`, `backups`, `dataLifecycle`, `accessControl`, `incidentNotification`,
`lawEnforcement` and `certifications`.

Claims may cite NIST SP 800-53 controls, FedRAMP Key Security Indicators and FedRAMP rules in `controlRefs`; their
ID formats are checked. Prose may use placeholders such as `{{org.name}}`, `{{contact.security}}` and
`{{doc.security-response}}`.

The JSON Schema is generated from the Go types, embedded as `schema.JSON`, and printed by `secdocs schema`.

### The `secdocs` CLI

| Command | Does |
|---|---|
| `init` | Writes a starter set where every claim is todo |
| `lint` | Reports what is invalid or still to be done, as text or JSON; `--fail-on` sets the exit threshold and `--strict` flags public claims that are not reviewed |
| `render` | Writes Markdown for an audience, with `--draft`, `--hide-gaps`, `--front-matter`, `--single` and `--json` |
| `export` | Writes the same audience's view as JSON |
| `security-txt` | Writes an RFC 9116 security.txt from the security-response document |
| `schema` | Prints the JSON Schema |

### Lint rules

- **Errors** cover invalid structure and values: required fields, enums, dates and URLs, duplicate IDs and slugs,
  unknown placeholders, missing facts, control ID formats, missing gap or justification text, expired
  certifications or security.txt, and contradictions between facts.
- **Warnings** cover what a publisher should still do: claims left as todo, missing or stale reviews, missing
  evidence, empty sections, weak TLS, and facts such as hosting location, backup retention or the notification
  window that are not stated.
- **Info** findings suggest improvements, such as a response target for reporters or a safe-harbor statement.

### Library

```go
set, err := spec.Load("security-docs.json")
report := lint.Run(set, lint.Options{})
files, err := render.Render(set, render.Options{Audience: spec.VisibilityPublic})
data, err := render.ExportJSON(set, spec.VisibilityPublic, false)
txt, err := render.SecurityTxt(set)
```

## Tests

- [examples/example-notes](https://github.com/opensecurity-dev/security-docs-spec/tree/main/examples/example-notes)
  is a complete fictional set. Its rendered public pages, NDA document, JSON export and security.txt are golden
  files, so any change to the output shows up in review.
- Leak tests check that content above the audience never appears in a public or NDA rendering, even in draft
  mode, or in the public JSON export.
