## [v0.1.0] - 2026-11-08

### Highlights

- An open JSON format for a cloud service's self-attested security documents, with typed facts stated once and claims that say how true they are
- `secdocs lint` reports what is invalid or still to be done, by rule ID and JSON path
- `secdocs render` and `secdocs export` publish Markdown and JSON from one audience-filtered view, so NDA and internal content cannot leak
- Builds only on sources that allow free commercial reuse: NIST SP 800-53, FedRAMP's 2026 rules and RFC 9116

### Added

- `spec` package: `DocumentSet` with shared fact groups and six typed documents (security overview, security response, subprocessors, data handling, incident response, availability) plus custom documents ([`85834a6`](https://github.com/opensecurity-dev/security-docs-spec/commit/85834a6))
- Claims with status, verification level, visibility, gaps, justifications, evidence and control references ([`85834a6`](https://github.com/opensecurity-dev/security-docs-spec/commit/85834a6))
- Placeholders such as `{{org.name}}` and `{{doc.security-response}}` in prose ([`85834a6`](https://github.com/opensecurity-dev/security-docs-spec/commit/85834a6))
- `spec.Load` and `spec.Scaffold` for reading a set and starting one where every claim is todo ([`85834a6`](https://github.com/opensecurity-dev/security-docs-spec/commit/85834a6))
- JSON Schema generated from the Go types and embedded as `schema.JSON` ([`3c5abf0`](https://github.com/opensecurity-dev/security-docs-spec/commit/3c5abf0))
- `lint` package: error, warning and info rules for structure, status, gaps, dates, reviews, placeholders, control ID formats and consistency between facts ([`6b28c41`](https://github.com/opensecurity-dev/security-docs-spec/commit/6b28c41))
